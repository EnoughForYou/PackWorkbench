### DOKUMEN BRIEFING: KUSTOMISASI RESOURCE PACK, FONT, MENUS, DAN INTEGRASI SERVER MINECRAFT (JAVA & BEDROCK) \#\#\#\# RINGKASAN EKSEKUTIF Pengembangan dan pengelolaan server Minecraft modern—baik Java Edition maupun Bedrock Edition—sangat bergantung pada kustomisasi visual, antarmuka pengguna (GUI), serta penyelarasan lintas platform ( _crossplay_ ). Dokumen briefing ini menyajikan sintesis komprehensif mengenai arsitektur _resource pack_ , pembuatan item dan pangkat ( _rank_ ) kustom, manipulasi font, konfigurasi menu, hingga prosedur teknis distribusi _resource pack_ di tingkat server. Poin-poin paling krusial dalam dokumen ini meliputi: \* **Dualitas Add-On Bedrock:** Ekosistem Bedrock membagi modifikasi menjadi _Resource Pack_ (RP) untuk visual/suara ( _client-side_ ) dan _Behavior Pack_ (BP) untuk logika/perilaku ( _server-side_ ). \* **Perbedaan Lintas Kompatibilitas (Java vs. Bedrock):** Konversi _texture pack_ dari Java ke Bedrock membutuhkan penyesuaian hirarki direktori, penamaan file, penggabungan peta UV ( _UV maps_ ), konversi animasi dari .mcmeta ke flipbook\_textures.json, serta penggunaan format TGA bersaluran _alpha_ ( _alpha channel_ ) untuk transparansi, _emissive_ , dan masker pewarnaan. \* **Kustomisasi Visual Antarmuka via Custom Fonts:** Pemetaan tekstur kustom (seperti ikon pangkat atau elemen HUD) dilakukan dengan memanfaatkan file JSON font (assets//font/) berbasis _provider_ bitmap dan space. Karakter Unicode khusus (misalnya \\uE000 hingga \\uE00E atau 0xE820) diintegrasikan dengan plugin izin seperti LuckPerms, LPC, dan TAB. \* **Penerapan Custom Model Data:** Penguraian item kustom 2D/3D pada Java Edition menggunakan struktur _predicate_ / _override_ di dalam file JSON model dasar (seperti diamond\_sword.json), yang kemudian dipanggil di dalam game melalui NBT tag CustomModelData. \* **Adaptasi Antarmuka Lintas Platform (DeluxeMenus & Bedrock Forms):** Menu GUI berbasis _chest_ pada Java Edition diadaptasi menjadi formulir _native_ Bedrock ( _Bedrock Forms_ ) melalui GeyserMC dan Floodgate, dilengkapi pengaturan otomatis ukuran baris ( _resize chest menus_ ) dan registrasi _skin-hashes_ untuk tekstur kepala ( _skulls_ ). \* **Standar Pemasangan Server-Side & Keamanan Cache:** Pengoperasian _server resource pack_ pada Java Edition mewajibkan penggunaan URL unduhan langsung ( _direct link_ ) dan kalkulasi _hash_ SHA-1 pada server.properties. Sementara pada Bedrock Edition, paket dipasang di folder resource\_packs dan didaftarkan melalui world\_resource\_packs.json berdasarkan UUID dan versi paket. \#\#\#\# 1\. ARSITEKTUR ADD-ON DAN PERBEDAAAN EKOSISTEM (JAVA VS. BEDROCK) \#\#\#\#\# 1.1 Struktur dan Pembagian Pack (Resource Pack & Behavior Pack) Dalam ekosistem Bedrock Edition, istilah _Add-On_ merujuk pada kombinasi dua jenis paket utama yang ditulis dalam format data terstruktur JSON, serta didukung aset gambar, suara, dan _JavaScript Script API_ : ┌─────────────────────────────────────────┐ │ ADD-ON │ └────────────────────┬────────────────────┘ │ ┌───────────────────────┴───────────────────────┐ ▼ ▼ ┌───────────────────────────────────┐ ┌───────────────────────────────────┐ │ Resource Pack (RP / Client) │ │ Behavior Pack (BP / Server) │ ├───────────────────────────────────┤ ├───────────────────────────────────┤ │ • Textures │ │ • Perilaku Entitas (Entity Logic) │ │ • Sounds │ │ • Resep Crafting (Crafting) │ │ • Geometry │ │ • Tabel Loot (Loot Tables) │ │ • Animations │ │ • Fungsi Kustom (Custom Functions)│ │ • Particles │ │ │ └───────────────────────────────────┘ └───────────────────────────────────┘ Kedua paket ini saling berkomunikasi. Sebagai contoh, ketika membuat entitas kustom, RP menentukan definisi entitas terkait tampilan visual ( _look_ ), sedangkan BP menentukan definisi entitas terkait logika perilakunya ( _act_ ). (Java ke Bedrock) Untuk mengubah paket tekstur Java menjadi paket Bedrock secara manual atau otomatis: 1\. **Pengadaan Referensi:** Dapatkan salinan paket tekstur Java kustom dan salinan paket tekstur _vanilla_ Bedrock terbaru sebagai Templat Utama. 2\. **Penyepadanan File:** Sandingkan jendela pengelola file Java dan Bedrock. Salin tekstur dari Java ke Bedrock hanya jika file tujuan yang sepadan ada di paket _vanilla_ Bedrock. File non-tekstur seperti data JSON atau .mcmeta milik Java **tidak boleh** disalin. 3\. **Pengkonversian Alat Automatis (Kastle Converter):** \* Gunakan alat _script_ java2bedrock.sh (Kas-tle converter). \* Unggah _resource pack_ Java ke platform seperti Dropbox, ambil link unduhan langsung (pastikan menggunakan parameter \&dl=1). \* Jalankan konversi untuk menghasilkan _resource pack_ Bedrock (.zip/.mcpack) serta file pemetaan kustom geyser\_mappings.json. \* Tempatkan _resource pack_ Bedrock hasil konversi di folder plugins/Geyser-Spigot/packs (atau Geyser/packs) dan file geyser\_mappings.json di folder Geyser/custom\_mappings. \#\#\#\# 2\. KUSTOMISASI FONT, TEKSTUR PANGKAT (RANK), DAN OVERLAY ANTARMUKA \#\#\#\#\# 2.1 Format File Font JSON dan Tipe Provider _Custom fonts_ memainkan peranan vital dalam modifikasi server-side karena memungkinkan penayangan tekstur gambar di lokasi mana pun pada layar (seperti elemen HUD, GUI kustom, atau indikator pangkat). File font disimpan pada direktori assets//font/ (misalnya default.json atau my\_font.json) dengan struktur utama berbasis array providers: json { "providers": \[ { "type": "bitmap", "file": "namespace:textures/path/image.png", "ascent": 8, "height": 8, "chars": \["\\uE000"\] }, { "type": "space", "advances": { "\\u2000": \-4 } } \] } _Deskripsi Tipe Provider Font:_ \* **bitmap** **:** Membaca karakter dari file PNG. Digunakan untuk menampilkan ikon, HUD, dan tekstur antarmuka. \* **space** **:** Mendefinisikan lebar spasi. Mendukung spasi negatif ( _negative spaces_ ) untuk menggeser kursor ke kiri dan penyesuaian posisi skala sub-GUI ( _sub-gui-scale movements_ ). \* **unihex** **:** Format berbasis teks heksadesimal untuk tekstur biner hitam-putih. \* **ttf** **:** Membaca font TrueType/OpenType (tipe ini tidak didukung oleh pustaka pengolahan font kustom seperti Nova). \#\#\#\#\# 2.2 Manipulasi Tata Letak Teks (Pergerakan Horisontal dan Vertikal) \* **Pergerakan Horisontal:** Memanfaatkan _space provider_ dengan nilai negatif. Spasi negatif mengizinkan karakter digambar di atas karakter sebelumnya, menciptakan efek latar belakang GUI atau overlay kompleks. \* **Pergerakan Vertikal:** Mesin Minecraft mengubah posisi vertikal karakter berdasarkan properti ascent pada _bitmap provider_ . Untuk menggeser font ke bawah sebesar 1 piksel, nilai ascent dikurangi 1 (misalnya ditambahkan offset \-1). Sistem seperti Nova membuat variasi font tergeser dengan penamaan direktori offset seperti //. \#\#\#\#\# 2.3 Pembuatan dan Integrasi Tekstur Pangkat/Rank Kustom Penggunaan tekstur ikon pangkat kustom (seperti pada paket _Nautical Ranks v2_ atau _Elec's Ranks_ ) dilakukan melalui langkah-langkah berikut: \#\#\#\#\#\# Modifikasi Paket Bedrock (.mcpack): 1\. Ubah ekstensi file .mcpack menjadi .zip, lalu ekstrak. 2\. Buka folder font dan ambil file glyph\_E8 (atau glyph\_E8.png). 3\. Impor file tersebut ke dalam program pengolah gambar (direkomendasikan Photopia atau Photoshop). 4\. Atur alat kuas ( _brush tool_ ) ke ukuran 1 piksel. Selaraskan posisi ikon pangkat baru di samping pangkat yang ada (admin, builder, mod) menggunakan bantuan alat bentuk persegi panjang ( _rectangle shape tool_ ) tanpa menyisakan celah piksel. 5\. Ekspor sebagai PNG, ganti file glyph\_E8 lama, lalu kompres ulang folder menjadi .zip dan ubah kembali ekstensinya menjadi .mcpack. 6\. Gunakan situs peta karakter untuk mengidentifikasi kode simbol Unicode yang terikat pada posisi piksel tersebut (misalnya 0xE820). \#\#\#\#\#\# Modifikasi Paket Java (.zip): 1\. Ekstrak paket Java, masukkan file gambar tekstur pangkat (PNG) ke direktori assets/minecraft/textures/ranks/. 2\. Buka file assets/minecraft/font/default.json menggunakan editor teks (seperti Notepad++). 3\. Salin blok _bitmap provider_ yang ada di bagian bawah file, ubah jalur file ke lokasi gambar pangkat kustom, lalu masukkan karakter simbol Unicode pada baris chars. 4\. Kompres kembali direktori assets, pack.mcmeta, dan pack.png menjadi file .zip. \#\#\#\#\# 2.4 Integrasi Simbol Rank dengan Plugin Izin (LuckPerms, LPC, TAB) Agar ikon pangkat muncul di depan nama pemain pada _chat_ dan _tab list_ : 1\. Pasang plugin LuckPerms, LPC (Chat Formatter), dan TAB pada server Java/Spigot. 2\. Daftarkan simbol Unicode yang sesuai dengan struktur pangkat berikut: \| Pangkat (Rank) \| Simbol Unicode Kustom \| \| \------ \| \------ \| \| **Admin** \| \\uE000 \| \| **Builder** \| \\uE001 \| \| **Developer** \| \\uE002 \| \| **Helper** \| \\uE003 \| \| **Hero** \| \\uE004 \| \| **Legend** \| \\uE005 \| \| **Megavip** \| \\uE006 \| \| **Mod** \| \\uE007 \| \| **Owner** \| \\uE008 \| \| **Player** \| \\uE009 \| \| **Twitch** \| \\uE00A \| \| **Ultravip** \| \\uE00B \| \| **Vip** \| \\uE00C \| \| **Vip+** \| \\uE00D \| \| **YouTube** \| \\uE00E \| 3\. Tetapkan pangkat pemain melalui perintah server: /lp user parent set 4\. Karakter simbol yang terpasang pada _prefix_ LuckPerms akan dibaca oleh _resource pack_ dan dirender sebagai tekstur ikon gambar di layar pemain. \#\#\#\# 3\. KUSTOMISASI ITEM DAN MODEL 3D DENGAN CUSTOM MODEL DATA \#\#\#\#\# 3.1 Penyiapan Aset Tekstur dan Model JSON Untuk membuat item kustom berbasis Java Edition (misalnya Pedang Zamrud kustom): 1\. Letakkan file gambar tekstur di direktori tekstur namespace kustom: resource\_pack/assets/minecraft/textures/custom/emerald\_sword.png 2\. Buat file JSON model di direktori model namespace kustom: resource\_pack/assets/minecraft/models/custom/emerald\_sword.json Untuk model 2D sederhana ( _generated model_ ), isi JSON model sebagai berikut: json { "parent": "item/handheld", "textures": { "layer0": "custom/emerald\_sword" } } _Catatan:_ Jika menggunakan model 3D kompleks yang dibuat melalui Blockbench, lakukan ekspor melalui menu File \> Export \> Export Block/Item Model untuk menghasilkan file JSON model secara otomatis. \#\#\#\#\# 3.2 Deklarasi Predicate / Override pada Model Dasar Vanilla Model kustom dihubungkan ke item dasar vanilla (misalnya Pedang Berlian) dengan menambahkan _predicate_ pada file model dasar yang terletak di /assets/minecraft/models/item/diamond\_sword.json: json { "parent": "item/generated", "textures": { "layer0": "item/diamond\_sword" }, "overrides": \[ { "predicate": { "custom\_model\_data": 1 }, "model": "custom/emerald\_sword" } \] } \* custom\_model\_data: Nilai integer unik yang digunakan sebagai penanda item. \* model: Jalur relatif menuju file JSON model kustom dari akar direktori /assets/minecraft/models/. \#\#\#\#\# 3.3 Pengujian dan Penggunaan Perintah In-Game Setelah paket sumber daya diaktifkan di dalam game, item kustom dapat diambil menggunakan perintah /give yang menyertakan tag NBT CustomModelData: /give @p minecraft:diamond\_sword{CustomModelData:1} \#\#\#\# 4\. PENGELOLAAN ANTARMUKA PENGGUNA (DELUXEMENUS DAN NATIVE BEDROCK FORMS) \#\#\#\#\# 4.1 Konfigurasi GUI Menu melalui DeluxeMenus Plugin DeluxeMenus digunakan untuk membuat menu GUI berbasis peti ( _chest menu_ ) yang kustom pada server Java. _Fitur & Persyaratan Utama:_ \* **Ketergantungan:** Membutuhkan **PlaceholderAPI (PAPI)** untuk menarik variabel data pemain ke dalam menu. \* **Struktur Konfigurasi:** Dikelola melalui file YAML pada direktori gui\_menus dan config.yml. \* **Ukuran Menu:** Ditentukan dalam kelipatan 9 slot (9, 18, 27, 36, 45, hingga 54 slot). \* **Komponen Barang (Items):** Mendefinisikan material, display\_name, lore, serta view\_requirement dan click\_requirement (persyaratan izin/akses). \* **Tipe Tindakan (Actions):** Mendukung eksekusi perintah seperti console, player, message, dan connect. \* **Perintah Reload:** /dm reload atau /deluxemenus reload. \#\#\#\#\# 4.2 Integrasi Native Bedrock Forms via GeyserMC dan Floodgate Pemain Bedrock yang terhubung ke server Java melalui GeyserMC sering kali mengalami kesulitan berinteraksi dengan GUI berbasis peti (karena ketiadaan fungsi klik-kanan atau Shift-klik pada layar sentuh/pengontrol). Plugin seperti _Phoenix Crates_ menyediakan fitur konversi GUI menjadi **Bedrock Native Forms** melalui integrasi Floodgate/Geyser: yaml bedrock: forms: true input-modes: \[\] allow-opt-out: true resize-chest-menus: true icons: enabled: true fallback-url: "" head-url: "https\://mc-heads.net/head/%texture%" _Detail Parameter Konfigurasi Bedrock Forms:_ \* forms: Mengaktifkan antarmuka _native_ Bedrock secara menyeluruh. Tampilan pratinjau hadiah, konfirmasi, dan kunci berubah menjadi tombol formulir Bedrock. \* input-modes: Menyaring penggunaan formulir berdasarkan jenis perangkat masukan pemain: TOUCH, CONTROLLER, KEYBOARD\_MOUSE, atau VR. Jika dikosongkan, seluruh pemain Bedrock akan menerima antarmuka formulir. \* allow-opt-out: Memungkinkan pemain Bedrock beralih kembali ke tampilan _chest menu_ biasa. \* resize-chest-menus: Mesin Bedrock hanya mampu menampilkan GUI peti 3 baris dan 6 baris secara rapi. Jika opsi ini bernilai true, menu 1-2 baris otomatis diperbesar menjadi 3 baris, dan menu 4-5 baris diperbesar menjadi 6 baris khusus bagi klien Bedrock. \* icons: Menambahkan ikon pada tombol formulir Bedrock menggunakan _texture material_ bawaan, fallback-url untuk item kustom, dan head-url untuk kepala pemain. \#\#\#\#\# 4.3 Registrasi Skulls/Player Heads untuk Bedrock (skin-hashes) Klien Bedrock tidak dapat memuat tekstur kepala pemain ( _player heads_ ) secara otomatis dari server tekstur Minecraft Java. Untuk animasi atau GUI yang menggunakan _custom heads_ , setiap tekstur kepala wajib didaftarkan pada konfigurasi skin-hashes milik GeyserMC. Format pendaftaran menggunakan bagian hash dari URL tekstur http\://textures.minecraft.net/texture/. \#\#\#\# 5\. DISTRIBUSI SERVER-SIDE, HOSTING FILE, DAN TROUBLESHOOTING \#\#\#\#\# 5.1 Pengaturan Server Resource Pack pada Java Edition Server Java dapat mengunduh dan mengaktifkan _resource pack_ secara otomatis kepada setiap pemain yang bergabung melalui konfigurasi file server.properties: properties resource-pack=https\://namaserver.com/pack.zip resource-pack-sha1=HASH\_SHA1\_ANDA require-resource-pack=true resource-pack-prompt={"text":"Server ini memakai tekstur kustom","color":"gold"} _Ketentuan Teknis:_ 1\. **Struktur Zip:** File pack.mcmeta wajib berada di **akar utama** direktori .zip, bukan di dalam subfolder. Nilai pack\_format harus sesuai dengan versi server. 2\. **Kalkulasi HASH SHA-1:** Digunakan untuk mendeteksi perubahan pada file paket agar klien memperbarui cache lokal mereka. \* _Linux / macOS:_ sha1sum pack.zip \* _Windows (PowerShell):_ Get-FileHash pack.zip \-Algorithm SHA1 3\. **Pemaksaan Paket:** Opsi require-resource-pack=true akan mengeluarkan ( _kick_ ) pemain yang menolak mengunduh paket. \#\#\#\#\# 5.2 Pengaturan Server Resource Pack pada Bedrock Edition Pada server Bedrock (BDS), paket sumber daya dipasang langsung di tingkat server tanpa memerlukan tautan URL eksternal: 1\. Ekstrak paket .mcpack ke dalam direktori /resource\_packs di akar server. Pastikan file manifest.json berada di akar folder tersebut. 2\. Buka manifest.json, catat nilai header.uuid dan version. 3\. Buka atau buat file world\_resource\_packs.json di dalam direktori /worlds//: json \[ { "pack\_id": "UUID-DARI-MANIFEST", "version": \[1, 0, 0\] } \] 4\. _(Opsional)_ Pada server.properties Bedrock, ubah texturepack-required=false menjadi true untuk mewajibkan paket, dan aktifkan content-log-file-enabled=true untuk melacak error. \#\#\#\#\# 5.3 Hosting File dan Pembuatan Link Unduhan Langsung (Direct Link) URL yang dimasukkan pada server.properties Java wajib berupa **link unduhan langsung** yang menghasilkan file .zip, bukan halaman landing web. \#\#\#\#\#\# Konfigurasi Hosting Dropbox: 1\. Unggah file .zip ke akun Dropbox. 2\. Buat tautan berbagi ( _share link_ ) dan pastikan akses diatur ke _"Siapa saja yang memiliki tautan dapat melihat"_ . 3\. Ubah tautan agar menjadi tautan unduhan langsung: \* Ganti akhiran dl=0 menjadi dl=1 atau \&dl=1. \* _(Atau)_ Tambahkan parameter ?direct di akhir URL file (misal: http\://example.com/pack.zip?direct). \#\#\#\#\# 5.4 Troubleshooting Masalah Umum \| Masalah / Pesan Error \| Penyebab Utama \| Solusi Penanganan \| \| \------ \| \------ \| \------ \| \| **"Failed to download resource pack"** \| Tautan bukan merupakan unduhan langsung ( _direct link_ ), atau server hosting lambat/dibatasi. \| Gunakan tautan langsung yang dapat diakses publik (misal: Dropbox dengan dl=1 atau web hosting mandiri). \| \| **Pack terunduh tetapi tekstur tidak berubah** \| File pack.mcmeta tersimpan di dalam subfolder, bukan di akar utama zip. \| Kompres ulang isi paket langsung dari dalam direktori paket (bukan mengompres folder terluar). \| \| **Pemain melihat tekstur versi lama** \| Nilai resource-pack-sha1 di server.properties tidak diperbarui setelah perubahan paket. \| Hitung ulang SHA-1 menggunakan PowerShell/sha1sum, lalu perbarui nilai resource-pack-sha1 dan restart server. \| \| **Peringatan "Incompatible"** \| Parameter pack\_format di pack.mcmeta tidak cocok dengan versi Minecraft server. \| Sesuaikan nilai pack\_format dengan spesifikasi versi server yang digunakan. \| \| **Tekstur transparan terender hitam / bug visual** \| Format PNG Java tidak menguraikan saluran _alpha_ Bedrock dengan benar. \| Konversi tekstur bermasalah ke format Targa (.tga) dan tetapkan masker saluran _alpha_ . \| \| **Formulir Bedrock tidak muncul (jatuh ke Chest Menu)** \| Modus input pemain tidak terdaftar, atau ketergantungan Floodgate/Geyser tidak aktif. \| Periksa opsi input-modes pada config.yml dan pastikan plugin Floodgate terpasang dengan benar. \|
